# Supervisord 升级重构方案

## 目标与交付约束

- 保留 Go 单个可执行文件 + INI/conf 配置的部署方式；Vue 构建产物、Coraza 和 OWASP CRS 规则全部嵌入二进制，运行端不需要 Node、Python、数据库或 CDN。
- 默认管理端口 `8002`，强制 HTTPS，首次初始化生成随机管理员账号、密码和自签名证书。密码只保存哈希；证书密钥与配置权限限制为 `0600`。支持替换可信证书。
- 先建立本方案及代码审计记录，再按下述顺序实施、回归；完成主要变更和验证后统一提交，不在每个小修改后提交。
- 保持原有 `[program:*]`、`[group:*]`、`[include]` 等配置语义；新增设置明确说明默认值、迁移行为和失败方式。

## 已确认的问题与核查边界

| 代码位置 | 已核实的行为 | 修复方向 |
| --- | --- | --- |
| `xmlrpc.go: readLogHtml` | 打开并不存在的 `webgui/log.html`，日志页面直接 404 | 统一 Vue 日志页和旧链接兼容路由 |
| `xmlrpc.go` | 文件目录通过 FileServer 暴露；部分配置/日志入口没有统一鉴权 | 只通过已鉴权的进程标识访问对应日志，取消目录浏览 |
| `logtail.go` | 等待日志通道时不监听请求取消；断开且无新日志时订阅不能清理 | 取消感知、有界缓冲、写超时、心跳和明确释放 |
| `process/process_manager.go` | `defer Unlock` 实际使遍历回调一直持有管理器锁；健康检查 goroutine 无停止入口 | 锁内快照、锁外回调；增加管理器关闭生命周期 |
| `process/command_parser.go` | 结束引号后立即提交参数，不能正确拼接引号片段；未闭合引号不报错 | 状态机解析、空参数、单/双引号、转义及异常用例 |
| `logger/log.go` | `backups=0` 禁止创建日志，与“关闭备份”的常用语义冲突 | 分离日志写入与备份数量，核查轮转/截断/并发读取 |

`directory` 已有部分代码，必须通过真实子进程验证相对路径、工作目录和日志路径，不能直接假设功能完全缺失。当前项目是进程管理器；媒体编码、推流协议和公网源重连只有在代码中存在实际实现时才列为缺陷，不将子进程内部问题冒充本仓库问题。

## 架构与页面设计

### 安全管理入口

1. TCP 管理服务仅接受 TLS 1.2+，支持 ALPN/HTTP2；明文 HTTP 不接受密码、会话或管理操作。
2. 提供网页登录、退出、当前会话及修改密码接口；使用随机会话令牌，服务端只保存令牌摘要，会话数量与有效期有界。
3. Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Strict`；写操作要求 CSRF 令牌并检查来源。登录错误统一返回，限制尝试频率和请求大小。
4. 旧 Basic Auth 不再作为网页认证方式；CLI、XML-RPC 和远程节点必须采用明确的安全认证迁移方案，禁止 `InsecureSkipVerify` 或默认放行。
5. Coraza + 内嵌 CRS 检查请求头、查询及请求体，开启阻断；SSE 不做响应体缓冲。WAF 初始化失败必须拒绝启用管理服务。
6. 不把 WAF 当作业务校验替代品：进程操作采用白名单、禁止任意文件路径读取，日志通过文本节点渲染。

### Vue + Vite + Element Plus

- 参考 `D:/Dday/go/tg-dice-service/web/src/app/` 与 `shared/style.css`：深绿色侧栏、浅灰工作区、白色卡片、紧凑边框、浏览器式多标签；不复制业务模块。
- 页面分为概览、进程管理、每进程日志、配置说明、安全/会话设置。统一封装 API、连接状态、进程状态标识、确认对话框和错误反馈。
- 标签页支持切换、关闭、关闭其他、深链接；关闭页面、退出登录及组件卸载时关闭连接、计时器与监听器。
- 概览与进程列表共用一个 SSE 状态流；日志仅活动页面订阅。连接中断使用有上限的退避，重连先获取快照，避免重复事件与无限内存缓存。
- 日志提供 stdout/stderr、暂停、清屏、下载、自动滚动和有界保留；支持轮转、长行、特殊进程名和重连。

## 进程与日志语义

- `directory` 相对路径基于配置所在目录解析，子进程通过 `cmd.Dir` 设置，不修改管理器全局工作目录。显式相对可执行路径也按工作目录解析。
- command 解析只生成 argv，不隐式执行 Shell；需要管道、重定向或变量展开时显式使用 `/bin/sh -c '...'`。单引号保持字面值，双引号与反斜杠采用文档化转义规则。
- stdout/stderr 独立配置，`redirect_stderr=true` 明确合并；相对文件路径基于程序工作目录；支持 `NONE`、`AUTO`、标准流及文件，不吞掉写入错误。
- 普通停止先发送 `stopsignal`，等待 `stopwaitsecs`，超时强杀；另提供明确的立即强杀操作与二次确认。停止后不得被 autorestart 拉起。
- 审计启动失败退避、父子进程回收、停止等待、stdin 管道、日志写入及健康检查超时，确保错误和退出路径都有资源释放。

## 7×24 小时代码审计与性能工作

逐文件阅读源代码及测试，在 `docs/CODE_AUDIT.md` 记录文件范围、证据、影响、修复与验证，不声明未经验证的“零泄漏”。重点检查：

- goroutine、channel、timer、ticker、文件、HTTP body/transport、TLS listener 与配置重载的所有权和退出路径；
- 全局注册表、文件变更监听、Prometheus collector 和事件订阅的重复注册/解除；
- 锁顺序、持锁 I/O、递归获取锁、数据竞态、忙等、无界重试和无界缓冲；
- HTTP 健康检查的连接复用、超时、异常响应关闭与最大响应体；网络不稳定时不让整个进程管理器阻塞；
- 共享状态采样、每进程指标采样、日志读写分配，先用 benchmark/pprof/压力数据定位，再优化；
- 重复函数/组件按真实职责合并，避免为了抽象制造新的重复层。

## 实施顺序与验收

1. **基础修复与审计**：命令解析、工作目录、日志轮转、停止/强杀、管理器/事件/健康检查生命周期；加入回归测试。
2. **安全入口**：HTTPS 初始化、会话登录、CSRF、Coraza、配置迁移、CLI 兼容；验证未登录访问、旧 Basic、明文请求均不放行。
3. **实时 API**：统一响应、进程操作、状态/日志 SSE、取消/背压/重连边界；循环连接断开验证订阅和资源回落。
4. **前端替换**：实现多标签工作台，修复旧日志链接；构建产物嵌入，离线验证无外部资源依赖。
5. **安装与交付**：`install.sh` 识别 Linux 架构，支持本地二进制与校验下载，初始化配置并安装/启动 systemd；重复执行保留配置、账号和证书。
6. **验证与统一提交**：Go 单测、vet、race（环境支持时）、Linux 交叉构建、前端单测/构建/浏览器验证、安装脚本检查与连接/重载压力测试。记录当前环境无法执行的项目，不能以交叉编译代替 Linux 实测。

验收必须覆盖：特殊字符进程名日志打开、无日志断连、stdout/stderr 分离、零备份写入、相对路径文件读取、混合引号 argv、优雅停止及立即强杀、会话过期/退出、SQLi/XSS 阻断、并发登录、连续重载与 SSE 断线重连。
